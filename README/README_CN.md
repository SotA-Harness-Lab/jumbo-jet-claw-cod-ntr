> *“小孩子才做选择，成年人我全都要。”*
>
> —— 网络流行语

Jumbo Jet ClawCod NTR（jjcn）是在 [ClawCod NTR](https://github.com/lutianyu2001/claw-cod-ntr) 之上重新打磨 harness 本身的版本。ClawCod NTR 是 OpenAI Codex CLI 的一个 fork，直接使用你为 Claude Code 准备的配置：`CLAUDE.md`、规则、skill、hook、设置、子代理和 MCP 服务器都在原处读取。本项目保留这一切，并加入对代理自身工作方式的改动，目标是下一代的代理 harness。

NTR 在这里是 Next-Tier Refined 的缩写：朝着下一代这个目标，一处一处打磨。在 ClawCod NTR 里这三个字母是 Native Tooling Ready，这一点在这里同样成立：Claude Code 原生的配置可以直接使用，不需要转换或迁移。

程序名是 `jjcn`。目前设置文件和环境变量仍沿用 ClawCod NTR 的（`ccn-config.toml`、`CCN_`），所以两者在同一台机器上共用一套设置；等 jjcn 的设置改用 Claude Code 的设置文件后就不再如此（见[方向](#方向)）。本仓库从 ClawCod NTR 的 `main` 复制而来，之后的更新也从那里取得。

目前加入的改动，逐项说明见 [jjcn refinements](../docs/jjcn.md)：

- 后台命令或后台代理结束时，空闲的会话会自己接着干。
- 回复被输出 token 上限截断时自动续写，而不是整轮失败。
- 一轮活干到一半就停下（只说下一步要做什么却不做、计划里还有没做完的步骤）时，送回去让模型接着做完。
- `Bash` 命令到了超时会留在后台继续运行；模型看不全的超长命令输出会存成文件供它读取。
- `Monitor` 把长时间运行的命令输出的内容告诉模型；`CronCreate`、`CronList`、`CronDelete` 让模型给自己安排定时提示。
- 所有提示词（包括 Codex 原有的）都是 [`prompts/`](../prompts/README.md) 下的文件，编译时嵌入程序，集中在一处查看和修改。
- 回退到更早的提示时，可以把此后被代理的编辑改动的文件一并恢复。

每一项默认开启，在 `~/.codex/ccn-config.toml` 的 `[harness]` 下各有开关。

## 概述

jjcn 保留 Codex 本身（模型、沙箱、审批、TUI 和 IDE 插件），在其上加一层兼容层，到 Claude Code 存放文件的地方直接读取。不复制、不转换，没有同步步骤；`CCN_CLAUDE_COMPAT=0` 可以关掉整个兼容层。Codex 已经有的机制，兼容层直接交给它做，只补上 Codex 没有的部分。逐项的说明见 [Claude Code compatibility](../docs/claude-compat.md)。

## 方向

jjcn 是 ClawCod NTR 的大改版。ClawCod NTR 保留 Codex，让它读懂 Claude Code 的配置；jjcn 则完全靠向 Claude Code 的生态：

- **配置与 Codex 的生态彻底脱离。** 设置全面采用 Claude Code 的设置文件，加上 jjcn 自己的设置文件，用 [layeredcfg](https://github.com/lutianyu2001/layeredcfg) 分层，jjcn 自己的设置文件优先于 Claude Code 的。
- **插件两边都兼容。** 插件系统同时加载 Claude Code 和 Codex 的插件。
- **大量新特性**：作者认为有用的都会加进来，打造一个适合作者自用的 harness；已加入的见 [jjcn refinements](../docs/jjcn.md)。
- **以 Codex 为底子，但不受它限制。** 需要多深的改动就改多深，同时继续跟进 ClawCod NTR 的更新。

以上是 jjcn 的方向，还没有全部做到：目前设置仍沿用 ClawCod NTR 的 `ccn-config.toml`。

## 功能特性

- **指令**：`~/.claude/CLAUDE.md`、项目的 `CLAUDE.md`、`.claude/CLAUDE.md` 和 `CLAUDE.local.md`（支持 `@` 引用），以及 `.claude/rules` 下的规则。带 `paths:` 的规则和子目录里的 `CLAUDE.md`，在读到或改到相应文件时才注入。
- **Skill**：`~/.claude/skills` 和各项目的 `.claude/skills`，支持 Claude Code 的 frontmatter（`disable-model-invocation`、`when_to_use`、`arguments`）。TUI 里用 `/<skill 名> <参数>` 调用，`$ARGUMENTS`、`${CLAUDE_SKILL_DIR}` 等都会替换。
- **Hook**：`settings.json` 里的 hook 照 Claude Code 的方式运行，包括 `Notification`、`PostToolUseFailure`、`StopFailure`，工具名和输入格式也和 Claude Code 一致；`PreToolUse` hook 可以放行、询问或阻止一次调用。
- **设置**：`env` 加进命令的环境变量；Bash 权限规则转成 Codex 的命令规则。
- **自动记忆**：读取项目的 `MEMORY.md`，并且按 Claude Code 的位置和格式写入新记忆，两个工具共用一份记忆。
- **自定义斜杠命令**：`~/.claude/commands`、项目的 `.claude/commands` 和插件的 `commands/` 在原处作为 skill 加载，名字取自路径（`git/commit.md` 就是 `/git:commit`，插件的是 `/<插件名>:<命令名>`）。
- **子代理**：`~/.claude/agents/*.md` 和项目的 `.claude/agents` 变成 agent role。
- **MCP 服务器**：`~/.claude.json` 里的，以及已批准的 `.mcp.json`。
- **插件**：Claude Code 里启用的插件在原处加载；用到 Codex 没有的机制（比如 Claude Code 的状态栏）的插件会被停用，除非在 `ccn-config.toml` 里手动启用。
- **Claude Code 的工具集**（可选，在 `ccn-config.toml` 里设 `[claude] tools = true`）：`Bash`、`Read`、`Write`、`Edit`、`Glob`、`Grep`、`WebFetch`、`WebSearch`、`TodoWrite`、`AskUserQuestion` 和 `Agent` 替换 Codex 自己的工具，作为一层架在它们之上；`Skill` 让模型带参数调用 skill。权限规则（`Read(...)`、`Edit(...)`、`WebFetch(domain:...)`）、子代理的 `tools` 和 hook 的匹配都能和 Claude Code 一一对应。和 Claude Code 一样，`Bash` 里的 `cd` 只要还在项目内就延续到下一条命令，`Read` 能逐个单元格读 notebook、逐页读 PDF（PDF 需要 poppler-utils：`pdftoppm`、`pdftotext`、`pdfinfo`）。

## 不兼容的部分

- `permissions` 里的 `defaultMode` 和 `additionalDirectories`、企业托管设置、输出风格和状态栏：Codex 没有对应的机制。
- skill 正文里的 shell 注入（`` !`command` ``），以及模型自己打开（而不是通过 `/<名字>` 调用）的 skill 里的替换。
- Claude Code 自己的模型和账号：jjcn 用的是 Codex 支持的模型。
- Windows：这个 fork 只构建 macOS 和 Linux 版。

## 安装

jjcn 还没有发布版，需要从源码构建。

### 从源码构建

见 [Installing & building](../docs/install.md)。装好 Rust 后，简单来说：

```shell
cd codex-rs
eval "$(bash ../scripts/fetch-rusty-v8.sh)"
cargo build --release -p codex-cli --bin jjcn
cargo build --release -p codex-code-mode-host
```

`scripts/fetch-rusty-v8.sh` 会下载构建时要链接的预编译 V8。

## 用法

在项目里运行 `jjcn`。登录方式和 Codex 一样：选 **Sign in with ChatGPT**，或者按 [Codex 的登录文档](https://developers.openai.com/codex/auth#sign-in-with-an-api-key) 配置 API key。

从源码构建的版本没有后台服务的安装包：启动 TUI 时用 `jjcn --no-daemon`。

要用 Claude Code 的工具集，新建 `~/.codex/ccn-config.toml`：

```toml
[claude]
tools = true
```
