ClawCod NTR 是 OpenAI Codex CLI 的一个 fork，直接使用你为 Claude Code 准备的配置：`CLAUDE.md`、规则、skill、hook、设置、子代理和 MCP 服务器都在原处读取，一套配置两个工具共用，在 `~/.claude` 里改了，Codex 下一次请求就能用上。

NTR 是 Native Tooling Ready 的缩写：Claude Code 原生的配置可以直接使用，不需要转换或迁移。

## 概述

ClawCod NTR 保留 Codex 本身（模型、沙箱、审批、TUI 和 IDE 插件），在其上加一层兼容层，到 Claude Code 存放文件的地方直接读取。不复制、不转换，没有同步步骤；`CCN_CLAUDE_COMPAT=0` 可以关掉整个兼容层。Codex 已经有的机制，兼容层直接交给它做，只补上 Codex 没有的部分。逐项的说明见 [Claude Code compatibility](../docs/claude-compat.md)。

## 定位

ClawCod NTR 是让 Codex 尽量完整地读懂 Claude Code 配置文件的版本。落到代码上：

- **优先在兼容层解决。** ccn 考虑兼容层内能完成的改动，以及只需小改 Codex 的特性。需要深入改造的特性，在兼容表里写清 ccn 能覆盖的部分和 jjcn 的目标。
- **其余保持 Codex 原样。** Codex 自己不冲突的特性都保留，不过保留它们本身不是目标。Codex 的代码只改兼容需要的部分，为的是能持续跟进上游 Codex 的更新：可以和上游有一定分叉，但始终保持在手动解决冲突就能合并的程度。
- **插件系统和程序设置沿用 Codex。** 它们是 Codex 的核心组件，不好大改，从头复刻一套兼容 Claude Code 的插件系统也没有必要。Claude Code 的插件在好做的范围内兼容；设置是 Codex 的 `config.toml` 和本改版的 `ccn-config.toml`，Claude Code 的设置只读兼容用得到的部分。

想要完全转向 Claude Code 生态的 harness，见在本项目之上构建的 [jjcn](https://github.com/SotA-Harness-Lab/jumbo-jet-claw-cod-ntr)。

## 设置从哪里来

ClawCod NTR 的设置来自三处。Codex 和 Claude Code 的文件都在原处读取，两边之间不复制任何东西。

| 来源 | 文件 | 管什么 |
| --- | --- | --- |
| **Codex** | `~/.codex/config.toml`（profile、`-c`）、`~/.codex/auth.json` | 程序本身：模型和服务商、推理强度、沙箱和审批、TUI、登录、会话和历史、Codex 自己的插件和插件市场、在这里声明的 MCP 服务器。和 Codex 共用。 |
| **Claude Code** | `~/.claude/` 和项目的 `.claude/`、`CLAUDE.md`、`~/.claude.json`、`.mcp.json` | 你为 Claude Code 准备的东西：说明和规则、skill 和命令、hook、权限规则、`env`、子代理、MCP 服务器、在 Claude Code 里启用的插件、自动记忆。`config.toml` 没设推理强度时，用 `effortLevel` 作默认值。 |
| **ClawCod NTR** | `~/.codex/ccn-config.toml` | 只有这个 fork 才有的：Claude Code 的工具集（`[claude] tools`）、被判为不兼容但仍要用的插件（`[claude.plugins]`）、在 hook 和子代理里代替 Claude 模型的 Codex 模型（`[hooks.models]`）、界面语言（`[ui]`）。 |

fork 自己的环境变量以 `CCN_` 开头。它的后台服务是自己的一份，和 Codex 的分开（`~/.codex/ccn-app-server-daemon`），登录和会话则共用。`ccn-config.toml` 的每个键见 [Claude Code compatibility](../docs/claude-compat.md#the-forks-own-settings-ccn-configtoml)。

## 功能特性

- **指令**：`~/.claude/CLAUDE.md`、项目的 `CLAUDE.md`、`.claude/CLAUDE.md` 和 `CLAUDE.local.md`（支持 `@` 引用），以及 `.claude/rules` 下的规则。带 `paths:` 的规则和子目录里的 `CLAUDE.md`，在读到或改到相应文件时才注入。
- **Skill**：`~/.claude/skills` 和各项目的 `.claude/skills`，支持 Claude Code 的 frontmatter（`disable-model-invocation`、`when_to_use`、`arguments`）。TUI 里用 `/<skill 名> <参数>` 调用，`$ARGUMENTS`、`${CLAUDE_SKILL_DIR}` 等都会替换。
- **Hook**：`settings.json` 里的 hook 照 Claude Code 的方式运行，包括 `Notification`、`PostToolUseFailure`、`StopFailure`，工具名和输入格式也和 Claude Code 一致；`PreToolUse` hook 可以放行、询问或阻止一次调用。
- **设置**：`env` 加进命令的环境变量；Bash 权限规则转成 Codex 的命令规则。
- **自动记忆**：读取项目的 `MEMORY.md`，并且按 Claude Code 的位置和格式写入新记忆，两个工具共用一份记忆。
- **自定义斜杠命令**：`~/.claude/commands`、项目的 `.claude/commands` 和插件的 `commands/` 在原处作为 skill 加载，名字取自路径（`git/commit.md` 就是 `/git:commit`，插件的是 `/<插件名>:<命令名>`）。
- **子代理**：`~/.claude/agents/*.md` 和项目的 `.claude/agents` 变成 agent role。
- **MCP 服务器**：`~/.claude.json` 里的，以及已批准的 `.mcp.json`。
- **插件**：Claude Code 里启用的插件在原处加载；用到 Codex 没有的机制（比如 Claude Code 的状态栏）的插件会被停用，除非在 `ccn-config.toml` 里手动启用。
- **Claude Code 的工具集**（可选，在 `ccn-config.toml` 里设 `[claude] tools = true`）：`Bash`、`Read`、`Write`、`Edit`、`Glob`、`Grep`、`WebFetch`、`WebSearch`、`TodoWrite`、`AskUserQuestion` 和 `Agent` 替换 Codex 自己的工具，作为一层架在它们之上；`Skill` 让模型带参数调用 skill。权限规则（`Read(...)`、`Edit(...)`、`WebFetch(domain:...)`）、子代理的 `tools` 和 hook 的匹配都能和 Claude Code 一一对应。和 Claude Code 一样，`Bash` 里的 `cd` 只要还在项目内就延续到下一条命令，`Read` 能逐个单元格读 notebook、逐页读 PDF（PDF 需要 poppler-utils：`pdftoppm`、`pdftotext`、`pdfinfo`）。

## 不兼容的部分

- `permissions` 里的 `defaultMode` 和 `additionalDirectories`、企业托管设置、输出风格和状态栏：Codex 没有对应的机制。
- skill 正文里的 shell 注入（`` !`command` ``），以及模型自己打开（而不是通过 `/<名字>` 调用）的 skill 里的替换。
- Claude Code 自己的模型和账号：ClawCod NTR 用的是 Codex 支持的模型。
- Windows：这个 fork 只构建 macOS 和 Linux 版。

## 安装

ClawCod NTR 还没有发布版，需要从源码构建。

### 从源码构建

见 [Installing & building](../docs/install.md)。装好 Rust 后，简单来说：

```shell
cd codex-rs
eval "$(bash ../scripts/fetch-rusty-v8.sh)"
cargo build --release -p codex-cli --bin ccn
cargo build --release -p codex-code-mode-host
```

`scripts/fetch-rusty-v8.sh` 会下载构建时要链接的预编译 V8。

## 用法

在项目里运行 `ccn`。登录方式和 Codex 一样：选 **Sign in with ChatGPT**，或者按 [Codex 的登录文档](https://developers.openai.com/codex/auth#sign-in-with-an-api-key) 配置 API key。

和 Codex 一样，`ccn` 把会话放在自己的后台服务里运行，关掉 TUI 后工作还能继续；这个服务和 Codex 的分开（`~/.codex/ccn-app-server-daemon`）。后台服务要从完整的程序包安装，单个可执行文件不行，所以先打包，再把包里的入口放到 `PATH` 上：

```shell
CODEX_REPO_ROOT=$PWD python3 scripts/build_codex_package.py --target <TARGET> --cargo-profile release \
  --entrypoint-bin codex-rs/target/release/ccn --code-mode-host-bin codex-rs/target/release/codex-code-mode-host \
  --rg-bin "$(command -v rg)" --package-dir <PACKAGE_DIR> --force
ln -s <PACKAGE_DIR>/bin/codex ~/.local/bin/ccn
```

`<TARGET>` 是你平台的目标三元组（`x86_64-unknown-linux-gnu`、`aarch64-apple-darwin`），`<PACKAGE_DIR>` 是你自己选的目录。包里的入口名叫 `codex`，它就是 ccn。在 Linux 上打包还会编译 `bwrap`，需要 libcap 的头文件；系统装了 bubblewrap 的话，改为传 `--bwrap-bin "$(command -v bwrap)"`。之后第一次运行 `ccn` 就会装好并启动后台服务；重新编译后，用 `ccn app-server daemon update --from-cli` 把新版放进去。不打包的话，启动 TUI 时用 `ccn --no-daemon`：服务就在 TUI 里运行，随它一起结束。

要用 Claude Code 的工具集，新建 `~/.codex/ccn-config.toml`：

```toml
[claude]
tools = true
```
